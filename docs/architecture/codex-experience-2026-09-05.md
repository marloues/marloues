# Codex 体验契约与真实任务验收

工作分支：`codex/architecture-review-20260905`。本记录接续 [真实长任务验收](real-long-tasks-2026-09-05.md)，描述当前工作树的增量修改。

## 产品验收原则

用户定义能力接口和对话展示契约，Runtime adapter 负责提供执行能力并归一化事件。优先使用 Runtime 原生能力，缺失能力再评估 patch；每个 Runtime 都可插拔，未来自研 Runtime 继续使用同一套交互体验。

Runtime 的消息列表、时间轴和轨迹是执行记录，不能直接决定用户界面。已有 18 类组件按宿主契约组织：过程、工具操作、审批和最终回答各有职责。体验以 Codex 为目标，包括运行中的反馈、完成后的折叠、可展开的完整详情、稳定滚动和明确的错误状态。样式和交互问题属于本次可直接修复范围。

## 本轮修改

- 读取操作统一展示目标文件名；兼容 `Read`、`read_file` 和带 server 前缀的工具名，大小写不再改变识别结果。Glob、Grep 分别展示查找模式和搜索词。原始工具名、参数和结果保留在详情中。
- 命令摘要识别字面量 `cd 路径 &&` 前缀，例如显示“已检查 Git 状态”；长命令只展示一次。完整命令仍用于详情与复制，不修改执行文本，不解释 shell 替换表达式。
- 分组摘要区分读取、搜索、查找，用顿号分隔；活动组运行标题与单个操作使用同一套命名规则。单文件参数对象按一个文件统计，避免把 JSON 的行数计为文件数。
- 修正长文本省略、图标与展开箭头被挤压、空 metadata 占位。失败摘要只显示一次失败文案，图标使用错误颜色，详情仍有独立状态与错误输出。
- 多条命令的摘要保留运行中、失败、停止状态，不再统一写成“已运行”。
- 修复真实 SDK 快速工具失败后的状态回退：实测 `Glob` 不可用时事件顺序为 pending → running → error → 迟到的 tool-start。adapter 不再重新发送已结束调用的开始/进度事件；宿主状态存储也保留同一 tool ID 的终态。重试使用新 tool ID，仍可正常运行。跟踪数据在 turn 结束或异常退出时清理。

## 真实任务记录

均使用开发应用的实际输入框，通过 SDK Runtime / DeepSeek 执行。未构造假的 UI 事件。任务只读项目源码，未安装、联网或使用子代理。

| 任务 | 耗时 | 工具调用 | 结果 |
| --- | ---: | ---: | --- |
| codex-experience | 76.9 秒 | 9 | 完成；发现快速失败后被迟到开始消息覆盖 |
| codex-scroll | 33.2 秒 | 4 | 完成；上翻后直到任务完成保持 scrollTop=1121 |
| codex-experience-fixed | 75.1 秒 | 9 | 完成；真实读取、命令、10 项定向测试通过；最终回答显示、过程自动折叠 |
| codex-error-recovery | 6.3 秒 | 2 | 首次读取不存在文件为 error，第二次读取真实文件为 completed，错误与成功输出均保留 |

合计约 191 秒、24 次真实工具调用，4 次任务均完成，观察器未记录 renderer error。第三次运行中模型确认 Glob/Grep 未注册，直接使用 Bash 替代，没有再次触发同一个 Glob 乱序；乱序修复由捕获的真实事件顺序对应的 adapter 和持久化回归测试验证，不能把第三次任务称为原故障的完整在线重现。

滚动曾出现看似自动回底的现象。追加记录后发现，回底期间收到了连续的正向 `wheel` 输入；上翻之后、这些输入之前没有程序调用 scrollTo/scrollBy，且未干预的另一轮一直保持位置。因此未据此修改滚动代码。原始第一次观察未带完整输入记录，不单独定性为产品缺陷。

应用内保留两个便于查看的会话：`真实体验验收 · 操作与滚动`、`真实体验验收 · Codex 展示`。前一个保留问题发生时的历史，后一个包含修改后的真实执行和失败恢复。旧会话的历史错误状态没有被伪造或回填。
