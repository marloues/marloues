# 组件内部交互规则

以下是源码中可定位的组件行为。它们补充上一阶段的执行状态规则；本次没有运行官方组件的整屏交互测试。

## 消息气泡与操作栏

来源：[C10](evidence.md#c10)、[C11](evidence.md#c11)、[C12](evidence.md#c12)。

| 编号 | 条件或动作 | 具体处理 |
|---|---|---|
| I01 | 用户消息允许编辑 | 同时需要 `onEditMessage`、turn ID，并排除合成的实施计划消息；不是每个用户气泡都显示编辑入口。 |
| I02 | 开始编辑用户消息 | 按 turn ID 保存编辑状态；已有草稿时不直接用原文覆盖。 |
| I03 | 提交编辑 | await `onEditMessage`；成功才清除编辑状态；失败 catch 分支不把草稿直接关闭。 |
| I04 | 复制用户消息成功 | 切换“已复制”图标/可访问标签，1500 ms 后恢复；反馈期间该复制入口不再次触发相同动作。 |
| I05 | 用户正文为空 | 是否展示空内容占位还结合附件、评论及特殊提示状态；不能用空字符串就把整条用户消息删除。 |
| I06 | 助手操作栏没有任何可用操作 | 如果也不满足单独显示时间戳的条件，组件返回 null。 |
| I07 | 助手操作栏未设置 alwaysShowActions | 通常透明，在气泡 group hover 或 focus-within 时显现；不是只做鼠标 hover。时间戳另有 hover 策略。 |
| I08 | 复制助手答复 | 可使用 `getCopyText / getCopyHtml` 获取内容，并写入纯文本或纯文本+HTML；复制文本不应直接取整块 DOM 的 innerText。 |
| I09 | 助手分支操作正在执行 | forkDisabled 或 isForking 为真时禁用分支按钮，使用 busy/loading 表现；click 阻止向外冒泡。 |
| I10 | 有历史实体且条目可被观察 | 助手包装可订阅对应 item 的更新；只读 async 条目等分支走直接渲染，交互不是由正文组件独自决定。 |

## 过程折叠与工具卡片

来源：[C13](evidence.md#c13)、[C14](evidence.md#c14)、[C15](evidence.md#c15)、[C16](evidence.md#c16)、[C32](evidence.md#c32)、[C34](evidence.md#c34)。

| 编号 | 条件或动作 | 具体处理 |
|---|---|---|
| I11 | 点击整段过程的折叠标题 | 先记录标题在时间线中的位置，再切换；锚点 helper 在短窗口内用 RAF/ResizeObserver 补偿位置变化，持续上限常量为 250 ms。 |
| I12 | 单个工具卡片 `status === running` | 内容默认展开，除非用户在运行阶段主动折叠；这个选择使用独立状态。 |
| I13 | 工具卡片不再 running | 展开依据另一份状态，初值来自 `defaultExpanded`；运行阶段展开不代表完成阶段必然仍展开。 |
| I14 | 工具卡片展开 | 仅由关变开时调用 `onExpand`；可用于上层延迟准备内容。没有 children 时，不提供同样的展开控制。 |
| I15 | 工具卡片收起 | 内容高度动画到 0，同时设置 `aria-hidden`、`inert` 和 `pointerEvents:none`，防止隐藏内容仍被键盘聚焦或点击。 |
| I16 | 工具内容高度变化 | 通过实际测量驱动高度动画；不能只写固定 max-height，否则大结果会被裁切或动画失真。 |
| I17 | 命令卡显示输出 | 命令与输出分别有复制入口；输出格式和内部滚动边缘表现独立处理。命令结果还分别接收成功、退出码、中断等字段。 |
| I18 | 展开/改变完成后的 diff 视图 | 组件也使用时间线锚点保持；接收 deferOffscreenRendering 来控制昂贵内容的呈现方式。 |
| I19 | thinking/等待槽位暂时不可见 | `Ii` 可以让文字 invisible、aria-hidden，同时保留槽位结构；不能一律用条件删除整行替代。 |

整段过程的折叠许可与单个工具的展开是两级状态。前者受“最终答复是否开始”等规则影响，后者受工具 running 状态和自己的局部选择影响。

## 输入框、主按钮与请求面板

来源：[C20](evidence.md#c20) 至 [C27](evidence.md#c27)。

| 编号 | 条件或动作 | 具体处理 |
|---|---|---|
| I20 | 富文本编辑器挂载 | 将 controller 已有的 `view.dom` 接入容器，而不是每次重建文本状态；安装尺寸观察与提交/建议事件处理器。 |
| I21 | 编辑器卸载或 controller 改变 | 解绑事件、断开观察、处理尚未结束的 composition 状态、关闭展开链接、blur 并移除对应 DOM。 |
| I22 | 自动聚焦 | `disableAutoFocus` 与 `focusRequestNonce` 共同决定；实际 focus 安排在下一帧，cleanup 会取消尚未执行的帧。 |
| I23 | 编辑器可访问名称 | 优先 `ariaLabel`，否则 placeholder；无值时移除 aria-label。最小高度可由 minHeight 覆盖，否则读取 CSS 变量并带回退。 |
| I24 | 点击 mention 或链接 | mention 可交给 `onMentionActivate`；文件 mention 有默认打开路径。富链接还有独立操作弹层，并维护 aria-expanded。 |
| I25 | 关闭富链接操作弹层 | 原链接节点仍连接时恢复其焦点，否则回到编辑器；不能无条件 focus 输入框。 |
| I26 | 主操作区选择按钮 | 根据 submitButtonMode、运行状态、恢复状态、队列策略等选择发送/停止/恢复；运行中的提交标签还区分 Queue 与 Steer。语音路径另有分支。 |
| I27 | 主按钮 loading 或 disabled | 使用不同的 aria-disabled、aria-busy 与原生 disabled 条件；loading 阻止提交。存在 blockedReason 时可保留非原生禁用节点，以承载原因反馈，但处理器仍阻止实际操作。 |
| I28 | 空消息提交被阻塞 | `blockedReasonOpenNonce` 可触发原因反馈；按钮不只是变淡而没有解释。 |
| I29 | 主按钮图标变化 | loading 可用 spinner；特定功能开关下发送/停止/语音图标可以形变；有 keyboardShortcutLabel 时可换成快捷键提示。 |
| I30 | 辅助控件需要适应输入区宽度 | `zLr` 测量总空间、尾部控件宽度和 gap，再把剩余空间交给相关控件；不是只依赖窗口断点。 |
| I31 | 出现待处理请求 | `wBr` 根据请求类型选择问题、选项、审批、授权或实施计划组件；问题与权限审批不共用同一份表单。 |
| I32 | 附件正在准备或已经准备完成 | 托盘接收不同数组与删除回调；来源包括图片、文件、粘贴文本、截图、选区和评论等，不能压成一个 filename 列表。 |

I20–I25 只描述富文本组件里已定位到的生命周期与交互。输入法确认时是否提交、所有发送快捷键和附件恢复范围，还需要继续追踪 controller 本身；本次没有据此宣称整个输入系统全部覆盖。

## 队列、侧栏与长列表

来源：[C26](evidence.md#c26)、[C29](evidence.md#c29)、[C30](evidence.md#c30)、[C31](evidence.md#c31)、[C35](evidence.md#c35)。

| 编号 | 条件或动作 | 具体处理 |
|---|---|---|
| I33 | 队列为空 | 队列组件返回 null。被用户中断时，有专门的队列暂停标题和恢复入口。 |
| I34 | 队列消息处于 paused | 增加警告提示；主动作从“现在发送”变为“重试”；提示建议重试、编辑或删除以继续队列。 |
| I35 | 队列有多条消息 | 才开启重排；drag 激活距离为 6 px。结束拖动时按稳定 ID 查找位置，没有目标、目标相同或 ID 无效则不发出重排。 |
| I36 | 队列行正在编辑或拖动 | 降低行透明度；拖动柄有独立 hover/drag 可见性；文本通常显示为单行摘要，可带小图片预览。 |
| I37 | 点击队列行内的发送/删除等动作 | 以 message ID 通知父组件，并阻止事件冒泡；不能让点击行内按钮同时触发整行其他动作。 |
| I38 | 摘要面板作为 popover 显示 | `shouldPreventAutoFocus` 可以阻止打开和关闭时的默认焦点移动；某些右侧 tab strip/tabpanel 的外部交互有专门的防关闭处理。 |
| I39 | 虚拟列表只渲染视口附近内容 | 记录各 turn 的测量高度和稳定 key；`retainedTurnKeys` 可以额外保留不在当前切片中的条目，所以“离开屏幕就立刻卸载全部组件”不成立。 |
| I40 | 需要导航到某条用户消息 | 导航轨道分别提供预览、揭示/跳转和书签回调；tooltip portal 和 reduced-motion 由参数注入；预览不应直接等同于改变当前阅读位置。 |

## 样式层同样有条件

来源：[C33](evidence.md#c33)。

资源里同时存在公共 token、平台覆盖、组件 CSS、单行/多行布局、表面/圆角变体及 reduced-motion 条件。例如：

- 公共 spacing 为 `0.25rem`，按钮尺寸以 spacing 倍数表达；平台还有覆盖，不能只取第一次出现的数值。
- 针对 browser / chrome-extension / electron 的 body 规则设有 `--thread-content-max-width:48rem`；文件里也有其他宽度和 utility 覆盖，最终值必须看实际元素的级联。
- 编辑器高度来自 `--composer-editor-min-height → --min-height-composer`；一些非默认表面/圆角组合会设置不同的最小高度、内边距和 placeholder 透明度。
- 滚动区 compact 呈现使用渐变 mask，底部渐隐与 `--thread-scroll-padding-bottom` 关联，并不是一张固定的半透明遮罩图片。

这些是静态样式声明，不是本次测量到的最终 computed style。要达到视觉一致，需要在目标平台、主题、字号和布局状态下验证级联结果。

## 建议的组件验收

下面为尚未执行的验收场景，用来把组件交互和执行规则接起来：

1. 编辑用户消息后提交失败，草稿和焦点是否仍可继续使用。
2. Tab 进入助手操作栏时，是否和 hover 一样可见。
3. 单工具运行时收起，再完成；整段过程同时折叠时，两个状态是否各自正确。
4. 收起的工具内容能否被键盘继续聚焦；高度变化时标题位置是否保持。
5. 在输入法 composition 期间切换任务，旧 DOM 与监听器是否清理正确。
6. 主按钮被阻塞时是否仍能读到原因，且鼠标/键盘都不能实际提交。
7. 关闭 mention/link 弹层后，焦点是否回到正确节点。
8. 队列行点击、拖动、编辑和立即发送是否互不误触发。
9. 打开摘要弹层再操作右侧标签页，面板和焦点是否按规则保留。
10. 长历史滚动与新回复流式增长交错时，测量高度、保留项和新回复位置是否稳定。
