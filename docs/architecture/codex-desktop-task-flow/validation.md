# 验证结果与验收场景

## 已完成的验证

分析的是包内版本 `26.901.41600`，不是网上截图或其他版本。证据索引包含 **9 个资源文件、46 组证据、94 个代码定位**。使用内置 Node API 读取 ASAR，校验包名、版本、资源文件 SHA-256 和每个定位片段 SHA-256；本次全部匹配。

对选取的原始函数执行了 **59 个边界探针，59 个通过**。[完整输入、期望值和实际值](probe-results.json)均已保存。

| 类别 | 已运行的内容 | 未由这些探针证明的内容 |
|---|---|---|
| 轮次状态 | 四种协议状态的展示映射 | 状态事件的网络先后顺序 |
| 计时 | 前置工作、插入位置、取消、缺失时间、空 final、结构化 final、sleep 识别 | 页面实际文案布局、秒级刷新和 sleep 调用点的整屏表现 |
| 折叠 | 三项许可条件、已有选择、forceExpanded 与 preventAutoCollapse 的优先级 | 点击、动画、折叠选择的持久化范围 |
| 阻塞请求 | 普通请求、三类特殊 elicitation、有无 turn ID | 真实审批交互与服务器执行结果 |
| 图片 | 完成图片、生成占位、停止、steer 重置、失败状态 | 图片加载、画廊渲染及 pptx 分支的真实界面 |
| 工作指示器 | thinking/exploring/planning/none、强制等待槽位、空 final 与有内容的 final | 外层全部可见性门控和最终 CSS |
| 终端输出 | 尾部保留、超长 delta、空 delta、零容量 | 实际终端控件、完整日志是否保存在其他位置 |

探针从经过哈希验证的资源中提取函数，在隔离的 JS context 中执行；没有重新抄写一个“相同算法”当被测对象。工作指示器的两个 import alias 连接到实际依赖函数：`Xn → W`、`ne → kGn`。测试未启动完整官方 App 模块，也未发送消息、作出审批或中断任何任务。

两个容易忽略的边界已实测：空且未完成的 final_answer 不会被当成已经开始展示的最终答复；停止后图片 `hasPendingItems` 可以仍为 true，而 `pendingPlaceholderCount` 已经为 0。

## 复核方式

在本文目录中执行，或把脚本名替换成绝对路径：

```sh
node inspect-bundle.mjs verify
node inspect-bundle.mjs show E34
node inspect-bundle.mjs show E31 --full
node probe-decisions.mjs
```

默认读取本次分析的安装路径。应用改名或移动后可追加 `--archive /新的路径/app.asar`。版本或哈希变化会报错，不能静默把旧偏移用于新包；届时需要重新提取定位。探针默认不写文件，只有显式加 `--write-results` 才更新结果 JSON。

## 覆盖边界

后续的[组件层分析](components/README.md)补充了富文本组件的生命周期、消息编辑/复制、按钮阻塞反馈和队列操作等内容。下列边界描述的是本篇执行流验证的范围；组件层新增的静态分析不能计入前述 59 个探针的通过数量。

已串起普通本地任务的提交协调、事件更新、请求处理、结束收尾、展示投影、过程聚合、折叠计时、图片输出、历史恢复和滚动主流程。表中的 110 条规则均有资源包证据，但其中只有上述纯函数子集做了执行验证。

本次还没有穷举：

- 输入编辑器的草稿保存、附件生命周期、IME/快捷键、粘贴、拖放和焦点恢复。
- 所有 Markdown/代码/公式/引用/链接渲染器以及文件预览、diff 编辑器内部交互。
- Aeon/语音/云任务及跨主机路径的完整控制、灰度开关和账号策略。
- 服务端重试、工具实际执行、持久化一致性及操作系统通知投递。
- 全部尺寸、配色、微动画、无障碍读屏以及实际长历史性能。

静态分析能揭示未亲手触发过的分支，但不能单独证明分支可达性和最终视觉。下一阶段优先按上面的事件场景回放；若目的是自己的产品，也应先决定哪些规则符合产品需求，再据此实现，而不是默认继承所有特殊分支。
